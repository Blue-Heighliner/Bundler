# Apt

Covers `AptBuilder`, `AptInstaller` and `DebIndex`: carrying Ubuntu packages to a computer with no network.

## Build

`AptBuilder.Prepare` creates an apt root in the cache that points at the Ubuntu 24.04 (`noble`) archive plus any extra sources a bundle names (the git-core PPA). The plan comes from `apt-get -s install` against the package list of the target system (`ITargetSystem`, the dpkg status of the system the installer USB drive installs, embedded as `Resources/target/dpkg-status.txt`), so the host's own packages never leak in and only what the target lacks is bundled, including newer versions of packages it has that something needs. A plan that would remove a target package is an error. Services are bundled even when the target has them already; support packages the target has are not asked for. `Plan` answers the same question without downloading, which the a2000 bundle uses to find a driver series whose packages fit the target kernel. `Scripts/UsbTarget.cs` rebuilds the target from the drive (`create`), refreshes the embedded list (`status`) and gives a clean copy for tests (`reset`). Each bundle splits its list into `top-level` packages (the services: their installed versions are compared and reported) and `support` packages (installed only when missing). `apt-get download` fetches the `.deb` files and `DebIndex` writes `Packages` and a `Release` without a date, so the same inputs give the same bytes and revisions stay stable.

## Install

The bundled folder is exposed as a `[trusted=yes] file:` source (symlinked from `/run`, which apt's sandbox user can read) and apt installs from it with no other source enabled and with `--no-remove`, so an install can fail but can never remove a package that is on the computer. When apt would have to remove packages anyway, the install stops with a message saying so (apt's own list of the packages is in the log above it) and nothing is changed. A bundle that has to replace something a different set of packages provides removes those packages itself, explicitly, with `RemoveInstalled` (the `a2000` bundle does this for an older NVIDIA driver series). Which packages were new is recorded in `apt-new`; only those are removed on uninstall, together with orphaned dependencies they pulled in (`APT::AutoRemove::RecommendsImportant=false`) and, for a driver bundle, old kernels except the one running.

A package that another bundle still needs stays when a bundle is uninstalled. It is written to `apt-leftover` next to the bundles' records, so the uninstall of whichever bundle is last removes it too; without that, libraries shared by two bundles would stay behind when the one that installed them is removed first.
